# 살까 말까 판독기 — 토스 미니앱

가격을 넣고 문항 세 개를 고르면 영수증 한 장이 인쇄된다. 하루당 얼마인지
계산해 주고, 그 계산이 반칙이면 반칙이라고 말한 다음, 구매 승인이나 반려를
찍는다.

웹 버전 없이 앱인토스만 있다. Vite + `@apps-in-toss/web-framework`.

## 개발

```bash
npm install
npm run dev      # 브라우저에서 확인 (네이티브 API는 조용히 무시된다)
npm run verify   # 판정 엔진 성질 검사
npm run build    # vite build && ait build
npm run deploy   # ait deploy
```

`npm run build` 가 `buyornot.ait` 을 만든다. 이 파일을 토스 개발자센터에
올린다.

### appName 은 콘솔 등록명과 같아야 한다

`apps-in-toss.config.ts` 의 `appName: "buyornot"` 은 토스 개발자센터에 등록한
이름과 **글자까지 같아야 한다**. 이 값이 번들 안 `bundle.json` 에 박혀서
업로드할 때 대조되기 때문에, 파일 이름이나 폴더 이름을 바꾸는 것으로는
해결되지 않는다. 콘솔에 다른 이름으로 등록했다면 여기를 고치고 다시 빌드한다.

## 판정은 전부 `src/verdict.ts` 안에 있다

외부 의존성이 없는 순수 함수다. 서버도, 모델 호출도, 난수도 없다. 같은
입력이면 언제나 같은 결과가 나온다. 승인번호까지 입력에서 뽑아내는 이유가
그것이다. 결과를 공유받은 사람이 같은 답을 넣었는데 숫자가 다르면 판독기가
아니라 룰렛이 된다.

화면(`src/App.tsx`)은 그 결과를 배치만 한다. 문구를 고칠 일이 있으면
`verdict.ts` 에서 고치고 검사를 다시 돌린다.

```bash
npm run verify
```

`scripts/verify.mts` 가 가격 19가지 × 문항 조합 64가지를 전부 돌리며 확인한다.

| 무엇을 | 왜 |
| --- | --- |
| 승인율 3~97%, 후회 4~96% | 판독기도 확신은 못 한다. 0%·100%는 쓰지 않는다 |
| 도장과 승인율이 맞는가 | 82%인데 "반려"가 찍히면 화면이 거짓말을 한다 |
| 단조성 | 술을 더 마셨는데 판정이 후해지면 안 된다 |
| 결정성 | 같은 입력에 같은 결과·같은 승인번호 |
| 판정 분포 | 뭘 넣어도 승인하는 기계도, 잔소리 기계도 아니어야 한다 |
| 공유 문구 | 화면에 보인 숫자가 그대로 실려야 한다 |

단조성 검사가 실제로 잡아낸 것이 하나 있다. 하루당 비용 구간의 낙차를 크게
잡으면 "한 달에 한두 번"으로 답을 바꿨을 때 예상 수명이 길어지면서 하루당
금액이 내려가고, 그 바람에 **덜 쓴다고 답했는데 승인율이 올라간다.** 그래서
구간 낙차(최대 9)를 사용 빈도 한 칸의 차이보다 작게 묶어 두었다. 계수를
건드릴 때 이 관계가 깨지면 검사가 멈춘다.

## 계산의 뼈대

| 답 | 예상 수명 | 총 사용 횟수 |
| --- | --- | --- |
| 거의 매일 | 2년 (730일) | 600회 |
| 일주일에 두세 번 | 3년 (1,095일) | 360회 |
| 한 달에 한두 번 | 4년 (1,460일) | 72회 |
| 솔직히 한두 번 | 1년 | 2회 |

하루당 = 가격 ÷ 수명일수, 1회당 = 가격 ÷ 총 횟수. 하루당 금액은 일상 물가
사다리(자판기 커피 500원 … 심야 택시 8만원)에서 바로 위 칸과 견준다.

세 지표는 서로 다른 것을 잰다.

- **소비 승인율** — 판정을 가르는 값. 66% 이상 승인, 50% 이상 보류,
  34% 이상 재고, 그 아래 반려. 조합을 고르게 훑으면 승인 19% · 보류 21% ·
  재고 22% · 반려 38% 로 나온다.
- **핑계 수준** — 얼마나 그럴듯하게 포장할 수 있는가. 하루당이 쌀수록,
  자주 쓸수록 오른다. **술을 마실수록 오른다.** 그게 이 앱의 농담이다.
- **내일 후회 확률** — 술과 중복 보유가 가장 크게 밀어 올린다.

그래서 "핑계 수준 S급 / 내일 후회 확률 91%" 같은 결과가 나온다. 새벽 세 시에
가장 근사한 논리를 세우고 가장 크게 후회한다.

## 네이티브 API

전부 `try/catch` 로 감쌌다. 토스 앱 밖(브라우저 개발 중)에서는 조용히 무시되고
웹 표준 동작으로 떨어진다.

| 용도 | API | 토스 밖에서는 |
| --- | --- | --- |
| 결과 공유 | `Share.sendMessage` | 클립보드 복사 |
| 선택 시 진동 | `Device.triggerHaptic` | 없음 |
| 노치·홈 인디케이터 | `SafeArea.get` / `SafeArea.subscribe` | `env(safe-area-inset-*)` |

권한은 하나도 요청하지 않는다(`permissions: []`). 값을 넣고 문항을 고르는 것이
전부라 카메라도 사진첩도 위치도 필요 없다. 서버도 없어서 입력한 금액은 기기
밖으로 나가지 않는다.

## 제출용 이미지

토스 개발자센터 "노출 정보" 규격에 맞춘 결과물이 `brand/out/` 에 있다.

```bash
npm run logo                    # 앱 로고 600×600 (라이트·다크)
npm run build && npm run shots  # 스크린샷
```

| 파일 | 규격 | 용도 |
| --- | --- | --- |
| `app-logo-600-light.png` | 600×600 | **앱 로고** |
| `app-logo-600-dark.png` | 600×600 | **다크모드 앱 로고** |
| `alt-won-600-*.png` | 600×600 | ₩? 만 남긴 대안 |
| `screenshots/portrait-*.png` | 636×1048 | **세로형 스크린샷** (6장, 최소 3장) |
| `screenshots/landscape-*.png` | 1504×741 | **가로형 스크린샷** (2장, 최소 1장) |

### 로고를 이렇게 정한 이유

앱 목록에서 아이콘은 60px 안팎으로 줄어든다. 그 크기에서 살아남는 건 글자
두어 개뿐이다. 영수증 그림도 그려 봤지만 톱니가 뭉개지면서 그냥 흰 사각형이
됐다. 남은 것이 이름 네 글자다. 두 줄로 넣고 붉은 도장 테두리를 두르면, 앱이
무엇을 하는지가 아이콘 안에 다 들어간다. `brand/logo.mjs` 에 ₩? 대안도 함께
두었으니 바꾸고 싶으면 거기서 고르면 된다.

### 스크린샷은 그림이 아니라 실제 캡처다

`brand/screenshots.mjs` 가 빌드된 `dist` 를 크로미움에 띄우고 금액을 치고
문항을 눌러 가며 찍는다. 손으로 그린 목업은 앱이 바뀌면 조용히 거짓이 되지만,
이건 언제나 현재 화면과 일치한다. 앱을 고쳤으면 다시 돌리면 된다.

제출 규격 636×1048 을 CSS 픽셀 그대로 쓰면 실제 휴대폰보다 넓고 짧은 화면이
되어 영수증이 가운데 400px 에만 서고 사방이 텅 빈다. 그래서 477×786 으로 띄우고
4/3 배로 찍는다. 636 과 1048 이 둘 다 정수로 나누어지는 배율이라야 하며,
1.5 배는 1048 이 나누어지지 않아 1px 이 어긋난다.

가로형만은 구성이 들어간다. 앱을 1504 폭으로 띄우면 영수증이 가운데 400px 에만
서기 때문에, 방금 찍은 세로 캡처를 그대로 얹어 가로로 배치한다. 새로 그리는 게
아니라 진짜 캡처를 놓는 것이다.

**폰트 주의**: 구글 폰트의 한글은 서브셋 수십 개로 쪼개져 있고 어느 파일에
어떤 글자가 들었는지 알 수 없다. `brand/fonts.mjs` 는 CSS 에 적힌 URL 을 전부
받아 통째로 resvg 에 넘긴다. 하나만 받으면(보통 마지막 = 라틴 서브셋) 한글이
통째로 빠진 채 렌더된다. 폰트 파일은 `brand/.fonts` 에 캐시되며 저장소에 넣지
않는다.

## 저장소 루트와의 관계

이 저장소 루트는 별개의 Next.js 앱이다. 두 가지를 맞춰 두어야 한다.

- `vite.config.ts` 의 `css.postcss: {}` — 빈 객체를 주지 않으면 vite 가 상위
  폴더를 타고 올라가 루트의 `postcss.config.mjs`(tailwind)를 집어 오고, 이 앱은
  tailwind 를 쓰지 않아 빌드가 그 자리에서 죽는다.
- 루트 `tsconfig.json` 의 `exclude` 와 `.vercelignore` 에 이 폴더를 넣어 두었다.
  빼면 루트 Next 빌드가 이 앱까지 타입 검사한다.
