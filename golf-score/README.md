# 골프 스코어 계산기 — 토스 미니앱

한 라운드를 홀별로 기록하고, 끝나면 스코어·미스 유형·지난 기록과의 차이를
돌려주는 앱인토스 미니앱. Vite + `@apps-in-toss/web-framework`.

```bash
npm install
npm run dev        # 브라우저에서 확인 (네이티브 API는 조용히 무시된다)
npm test           # 타수·분석 계산 검증
npm run smoke      # 빌드된 앱을 크로미움에 띄워 실제로 눌러 본다
npm run build      # vite build && ait build
npm run deploy     # ait deploy
```

## 서버가 없다

기록은 전부 기기 안(토스 `Storage`)에만 남는다. 골프장은 통신이 자주 끊기고
라운드 하나를 넣는 데 네 시간이 걸린다. 네트워크에 기대는 순간 필드에서 못
쓰는 앱이 된다. 그래서 로그인도, 계정도, 서버 호출도 없다.

`Storage` 는 앱을 종료해도 값이 유지되는 네이티브 저장소다. 토스 앱 밖에서
개발할 때는 호출이 실패하므로 `localStorage` 로 떨어진다(`src/storage.ts`).

홀을 넘길 때마다 진행 중인 라운드를 통째로 덮어쓴다. 앱이 죽어도 홈 화면의
**이어서 하기**로 그 홀부터 다시 시작한다.

## 타수는 이렇게 센다

```
홀 스코어 = 친 샷 수 + 벌타 + 퍼트 수
```

퍼트를 샷 목록에 넣지 않는 이유는 그린 위 스트로크를 따로 세어야 퍼트 평균과
파온율이 나오기 때문이다.

| 샷 결과 | 벌타 |
| --- | --- |
| OB (좌·우) — 특설티 규칙 | +2 |
| OB (좌·우) — 정규 규칙 | +1 |
| 해저드 (좌·우) | +1 |
| 러프·벙커 | 0 (위치만 기록) |
| 뒤땅·탑볼·뽕샷·생크 | 0 (미스 유형만 기록) |

**OB 를 어떻게 셀지는 라운드마다 고른다.** 국내 주말 라운드에서 흔한 특설티
(전진티)는 앞으로 나가는 대신 벌타를 2 먹는다. 원래 자리에서 다시 치는 정규
규칙(스트로크 & 디스턴스)은 벌타가 1이다. 기본값은 특설티다.

파온(GIR)을 셀 때는 **벌타를 반드시 함께 센다**. 파5에서 티샷 OB 를 내고 세
번 쳐서 올렸다면 샷 수는 3이지만 실제로는 5타째에 올린 것이라 파온이 아니다.

## 입력을 짧게 만든 두 가지

요구대로 샷마다 클럽과 결과를 다 고르게 하면 18홀에 130탭이 넘는다. 필드에서
장갑 끼고 그걸 하면 세 홀 만에 앱을 닫는다.

1. **미스만 찍는다.** 결과의 기본값이 "정타"고, 샷 개수도 파에 맞춰 미리
   깔려 있다(파3은 1샷, 파4는 2샷, 파5는 3샷). 퍼트 기본값은 2다. 그래서
   손대지 않은 홀은 그대로 파가 된다.
2. **한 홀이 한 화면에 들어간다.** 스크롤 없이 다음 홀로 넘어간다.

파는 홀 화면에서 바로 바꿀 수 있고, 아직 손대지 않은 홀이면 샷 줄도 새 파에
맞춰 따라온다.

## 분석은 전부 산술이다

`src/analysis.ts` 가 하는 일은 집계뿐이다. 없는 데이터를 그럴듯하게 지어내지
않는다. LLM 을 끼우지 않은 것도 같은 이유다 — 같은 기록에 매번 다른 표현이
나오면 "지난번보다 나아졌는가"를 견줄 수 없다.

- 방향 편향 (좌 미스 vs 우 미스 → 훅·슬라이스 경향)
- 임팩트 미스 빈도 (뒤땅·탑볼·뽕샷·생크)
- 벌타 손실, OB·해저드 횟수
- 퍼트 총계·홀당 평균·3퍼트 홀 수
- 파온율(GIR), 페어웨이 안착률
- 파별 평균 타수, 전·후반 격차
- 클럽별 안정도

**한줄요약**은 위 지표에 "이것 때문에 잃은 타수"로 가중치를 매겨, 가장 큰 손실
원인 하나와 가장 잘한 것 하나를 문장에 끼운다.

**추세**는 지난 5라운드 평균과 견준다. 다만 **이전 기록이 2개는 있어야**
말한다(총 3라운드). 한두 번 치고 "좋아지고 있어요"를 띄우면 그냥 거짓말이다.
9홀과 18홀을 섞어 쳐도 비교되도록 전부 18홀 환산 타수로 견준다. 예전 기록을
다시 열어 보면 **그 라운드보다 먼저 친 것들과만** 견준다.

## 네이티브 API

전부 `try/catch` 로 감쌌다. 토스 앱 밖에서는 조용히 무시되고 웹 표준 동작으로
떨어진다.

| 용도 | API |
| --- | --- |
| 라운드 기록 저장 | `Storage` |
| 라운드 중 화면 꺼짐 방지 | `Screen.setAwakeMode` |
| 결과 공유 | `Share.sendMessage` |
| 터치 진동 | `Device.triggerHaptic` |
| 노치·홈 인디케이터 | `SafeArea.get` / `SafeArea.subscribe` |

`setScreenAwakeMode`, `share`, `generateHapticFeedback` 는 deprecated 라 쓰지
않는다.

권한은 하나도 요청하지 않는다(`permissions: []`). 카메라도 위치도 필요 없다.

## 검증

`npm test` 는 화면 없이 `score.ts` · `analysis.ts` 만 확인한다. 이 앱에서
틀리면 안 되는 것은 타수다. 벌타를 하나 잘못 세면 그 라운드만 틀리는 게
아니라 "나아지고 있는가"라는 추세까지 같이 틀어진다.

`npm run smoke` 는 빌드된 앱을 크로미움에 띄우고 실제로 눌러서, 누른 값이
화면에 그대로 나오는지와 새로고침 후에도 기록이 남는지를 본다.

## 배포 전에 고칠 것

`apps-in-toss.config.ts` 의 `appName` 이 `golfscore` 로 되어 있다. **토스
개발자센터에 등록한 이름과 반드시 같아야 한다.** 이 값이 번들 안
`bundle.json` 에 박혀서 업로드할 때 대조되므로, 파일 이름을 바꾸는 것으로는
해결되지 않는다.
