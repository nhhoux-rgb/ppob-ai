# 도전권 · 연습모드 · 광고 · 유료결제 설정

## 정책 요약
- **하루 도전권 10장** (매일 KST 기준 최소 10장으로 채움. 구매·적립분은 유지)
- **랭킹전**: 1판당 도전권 1장 사용 → 랭킹 반영
- **연습모드**: 도전권 없이 무료 · 랭킹 미반영
- **친구 공유**: +1장 (하루 5회까지)
- **광고 시청**: +5장
- **유료 구매**: 30장 / 990원
- **랭킹**: 분야별(경제·시사·국제·역사) 탭

수치는 `src/config.js`(프론트)와 `backend/supabase-edge-tickets.ts`(서버) 양쪽에 있어요. 바꾸려면 둘 다 맞춰주세요.

## 1. Supabase 배포 (도전권 서버)
1. SQL Editor에서 `backend/supabase-tickets-schema.sql` 실행 (테이블 2개 생성)
2. Edge Function 배포 (JWT 검증 off):
   ```bash
   supabase functions deploy tickets --no-verify-jwt
   ```
   - `tickets` ← `backend/supabase-edge-tickets.ts`
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`(기본 제공) 사용

→ 이 시점부터 **하루 10장·공유·연습·랭킹전**이 모두 동작해요. (광고·결제는 아래 설정 후)

## 2. 광고(+5) 켜기
1. 앱인토스 콘솔 > **광고**에서 보상형 광고그룹 생성 → **광고그룹 ID** 확보
2. `src/config.js`의 `TOSS.adGroupId`에 그 값을 넣기
3. 다시 빌드(`pnpm build`) 후 `.ait` 재배포

> 값이 비어 있으면 상점의 광고 버튼은 "준비 중"으로 표시돼요(앱은 정상).

## 3. 유료결제(30장/990원) 켜기
1. 앱인토스 콘솔 > **인앱결제**에서 상품 등록:
   - 상품: 도전권 30장, 가격 **990원**, 소비성(consumable)
   - **SKU**(상품 식별자) 확보
2. `src/config.js`의 `TOSS.purchaseSku`에 SKU 넣기
3. 다시 빌드 후 `.ait` 재배포

구매 흐름: 앱이 `IAP.createOneTimePurchaseOrder({sku})` → 결제 성공 시 `processProductGrant(orderId)`에서 서버(`tickets` purchase, orderId 멱등)로 30장 지급.

> ⚠️ 보안: 현재는 결제 성공 콜백에서 바로 지급해요. 실서비스 정식 운영에서는 **서버가 orderId를 토스 결제 API로 재검증**(정식 서버 로그인/복호화키 기반)하는 걸 권장해요. 광고 보상도 마찬가지로 서버 검증을 붙이면 어뷰징을 막을 수 있어요.

## 확인
- 홈 헤더에 `🎟️ 숫자`(도전권), 모드 토글(랭킹전/연습)
- 랭킹전 1판 → 도전권 1 감소 / 연습 → 변화 없음, "연습 완료(랭킹 미반영)"
- "도전권 얻기"에서 공유 +1, (설정 시) 광고 +5, 구매 +30
