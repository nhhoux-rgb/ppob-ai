# 랭킹 + 토스 로그인 연동 안내

이 버전에서 `platform.js`의 mock을 실제 토스 로그인으로 바꾸고, 분야별 랭킹(리더보드)을 추가했습니다.

## 1. 동작 개요

- **로그인/신원**: `User.getAnonymousKey()`로 사용자 고유 해시를 받아 랭킹 식별자로 사용합니다(로그인 시 동의창 없음).
- **표시 이름**: `getConsentedUserData({ consentedUserDataKey: 'user_name' })`로 토스 이름을 가져옵니다. **약관이 등록돼야 동작**하며(에러코드 `TERMS_NOT_SET`), 실패·거부 시 `게스트####`로 표시합니다.
- **랭킹 지표**: 연속 정답 수(내림차순) → 총 풀이 시간(오름차순). 분야별 최고 기록을 저장합니다.
- 토스 밖(웹 미리보기)에서는 localStorage 게스트 신원으로 폴백해 그대로 동작합니다.

## 2. Supabase 배포 (랭킹 백엔드)

프로젝트: 프런트가 이미 `euifgvsbvqjkzxljmxnl` 프로젝트를 바라봅니다(`src/rank-api.js`).

### 2-1. 테이블 생성

`backend/supabase-leaderboard-schema.sql`을 SQL Editor에서 실행합니다. (`leaderboard_scores` 테이블 + 인덱스 + RLS)

### 2-2. Edge Function 배포

두 함수를 각각 배포합니다. **JWT 검증은 꺼야** 앱에서 직접 호출됩니다.

```bash
# 파일명을 함수 디렉터리(index.ts)로 맞춰 배포
supabase functions deploy submit-score --no-verify-jwt
supabase functions deploy leaderboard  --no-verify-jwt
```

- `submit-score` ← `backend/supabase-edge-submit-score.ts`
- `leaderboard`  ← `backend/supabase-edge-leaderboard.ts`

두 함수는 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` 환경변수(기본 제공)를 사용합니다.

## 3. 앱인토스 콘솔 설정

1. **동의 항목**: 이름(`user_name`) = 필수 동의(현재 설정 유지).
2. **약관 URL**: 서비스 이용약관 페이지 URL 등록(이름 조회에 필요).
   - 이름 동의를 못 받아도 게스트로 랭킹은 동작합니다.
3. 연결 끊기 콜백: 이름만 받는 구성이면 생략 가능.
